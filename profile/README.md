<h2>一条专线内做池，和跨线路做池不是一回事</h2>
<p>跨线路的池，每个地址在不同线路上，故障域独立。一条专线内的池，所有地址共享同一条线路的带宽与链路质量，一个故障可能让全池不可用。</p>
<p>这个差别决定了设计重点不同：跨线路的池要解决「怎么调度」，单线路的池要先解决「故障时不至于全灭」。</p>

<h2>池化的三个前提</h2>
<p>一，地址数量够用。至少够每组一个，再加一个备用。二，地址属性一致。同一条专线分配的地址通常同段，属性接近，这反而有利于统一管理。</p>
<p>三，有统一的接入入口。如果每个地址都靠使用者自己填配置，那就不是池，只是一堆地址。池的本质是「使用者不关心具体地址，由系统分配」。</p>

<h2>第一步：地址清单化</h2>
<p>把这条专线上所有可用地址列成清单，每行记：地址、状态（可用/占用/冷却/停用）、当前绑定对象、最近变更时间。</p>
<p>清单是池的地基。没有清单，调度就只能靠记忆，而记忆在多地址场景里一定会出错。</p>

<h2>第二步：统一接入入口</h2>
<p>让所有使用者连同一个入口，由入口按规则分配出口地址。这样使用者不需要知道具体地址，地址变化也不影响他们。</p>
<p>接入入口要做两件事：认证与分配。认证到人，分配有规则。两者都做好，池才算跑起来。</p>

<h2>第三步：调度规则</h2>
<p>单线路池里最常用的是「粘性绑定」：一个使用者或一个账号固定用一个地址，直到明确更换。这比轮换更稳，因为地址稳定本身就是价值。</p>
<p>轮换只适合短时、分散的访问需求。用于长期账号，会让登录地频繁变化，得不偿失。</p>

<h2>第四步：监控与剔除</h2>
<p>要监控两项：地址可用性与使用强度。不可用的地址及时摘除，避免使用者连上去发现不通；使用强度过高的地址要限流，避免单点跑满影响全池。</p>
<p>剔除之后要有补充机制。池里的地址少了，剩余地址压力上升，容易进入恶性循环。</p>

<h2>常见的设计错误</h2>
<p>一是把池做成「随机分配」。使用者每次连上拿到不同地址，看起来灵活，实际让每个账号的登录地都在变。二是没有冷却期，地址回收立刻给别人用，痕迹直接继承。</p>
<p>三是没有统一入口，靠手工填配置。地址一多就乱，出问题也无法追溯。四是忽视全池故障风险，一条线路出问题，所有使用者同时受影响。</p>

<h2>维护节奏</h2>
<p>每周看一次池的健康度：可用率、平均使用强度、失败次数。每月做一次地址轮换评估：长期表现差的换掉，但换之前先确认不是使用方式的问题。</p>
<p>每次新增或停用地址都同步更新清单。清单与实际情况脱节的那一天，就是池开始失控的起点。</p>

<p>一条线路承载多个住宅地址时，关键是让每条地址对应独立的出口规则。常见错误是把所有地址配在同一张网卡上而不做策略，结果对外只暴露一个出口。配置完成后逐条验证出口，是唯一可靠的确认方式。</p>
<h2>常见问答</h2>
<h3>一条专线上做池有意义吗？</h3>
<p><strong>答：</strong>有，但要注意全池同源的风险。所有地址共享一条线路，故障时会一起受影响。</p>
<h3>池里的地址能随便换吗？</h3>
<p><strong>答：</strong>技术上能，但不建议频繁换。地址稳定本身就是价值。</p>
<h3>需要专业软件吗？</h3>
<p><strong>答：</strong>小规模用代理服务加一张表就够。规模大了再考虑更完整的方案。</p>
<h3>怎么防止一个人跑满全池？</h3>
<p><strong>答：</strong>按用户或按地址限速。这一项在单线路池里几乎是必需的。</p>
